## 2. Metal backend — root cause CONFIRMED (critical)

`work/wsclean/metal/metalinversion.mm:286-289` redeclares `item_count`,
`w_lambda`, `w_sign`, `w_min`, `w_max` **inside** `if (input.w_gridding)`,
shadowing the outer declarations at `:277-280`. The inner fill dies at `:309`;
after that `:311` computes `w_max - w_min` from the outer zeros (0 range),
and `:405,455,476` read the still-empty outer vectors — heap OOB, garbage `w`
per visibility. Signature match is exact: visibilities still grid (power right)
but plane assignment, `wWeight`, and screen use garbage (corr 0.056). Fix is
four lines: drop the shadowing declarations, resize the outer vectors, reset
min/max. Subsidiary hypotheses H2–H5 (tile-rounded cell scale, `wWeight` vs
`eval2s`, plane-FFT extraction, FixW ordering) stay open until the M1
plane-level tests run — H1's garbage may be masking them. Perf: full MSL
recompile + new queue per plane call (`metaldevice.mm:205-215`) explains the
4.5× slowdown; float CAS never converges on NaN (`mxshaders.h:24-48`, hang risk).
