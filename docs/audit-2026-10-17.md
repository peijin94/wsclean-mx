## New allocation optimization: correctness and measured performance

The RED test called the public production multiscale-peak API and counted full-image array allocations. Before the change, all four unweighted scenarios allocated two images instead of one and failed; all four weighted controls passed. After the change, **all eight scenarios pass**: one allocation without RMS weighting, two with it.

This removes one `width × height × 4`-byte allocation request per unweighted scale search: 16 MiB at 2048². The old unused buffer was neither initialized nor touched, so this is **not a guaranteed 16 MiB RSS saving**.

End-to-end deterministic check: **all five FITS products are bitwise identical** between freshly built pre/post binaries at `-j 1`, 1024², full-sky multiscale, niter 300: dirty, restored image, model, PSF, residual. See `p12-exact-comparison.log`.

Four fresh alternating-order repetitions at 2048², niter 3000:

| Measurement | Fresh p11 baseline | Conditional scratch |
|---|---:|---:|
| Wall samples | 24.14, 16.51, 17.64, 19.53 s | 17.69, 17.04, 14.71, 14.84 s |
| Wall median | 18.585 s | 15.940 s |
| Deconvolution median | 6.397 s | 4.999 s |
| Inversion median | 7.2015 s | 6.9605 s |
| Prediction median | 3.8030 s | 3.0405 s |

The observed median wall ratio is approximately **1.17×**, but **no reliable additional speedup is claimed**. Spread is large, unrelated prediction/inversion stages changed, and this session was substantially slower than the initial benchmark. The host was not idle: load averages reached about nine and roughly 12 GiB of swap remained occupied. The justified result is removal of the unused allocation plus deterministic output preservation. Repeat timing on a quiet/cool host before treating the ratio as an optimization effect.

## Numerical comparison results — including failures

Default T2 limits were kept unchanged: relative RMS `1e-4`, relative peak `1e-3`. No tolerance was loosened after examining results.

### Existing mx-p11 versus upstream-fix

- 4096² dirty: all products in all three paired runs pass; relative RMS **7.11e-7–7.35e-7**. Upstream reruns: **5.98e-7–6.05e-7**.
- 2048² multiscale dirty and PSF: all paired runs pass, approximately **5e-7–7e-7** relative RMS.
- Multiscale **restored/model/residual fail default T2**, and upstream's own reruns fail these strict limits too.

| Product | mx-p11 vs upstream-fix relative RMS range | Upstream rerun range |
|---|---:|---:|
| Restored image | 0.01356–0.01474 | 0.002881–0.008582 |
| Model | 0.05643–0.09460 | 0.03989–0.09210 |
| Residual | 0.01915–0.02645 | 0.006211–0.02080 |

Residual RMS is close: upstream **24.641–24.652 µJy**, mx-p11 **24.657–24.659 µJy**. However, the restored-image differences exceed this session's sampled upstream-rerun range. Therefore “all images are within upstream's own rerun spread” is **not justified by these new runs**. README wording has been narrowed. This does not establish a scientific defect by itself: multiscale is sensitive to earlier FFT rounding, and broader perturbed-reference/source-level tests are needed.

### Conditional scratch versus the fresh p11 baseline

- Dirty/PSF products pass default T2 in all four paired runs.
- Cleaned products fail default T2, but their paired relative-RMS ranges lie within the **fresh p11 baseline's own sampled rerun maxima**: restored max 0.014918 vs 0.014955; model 0.090748 vs 0.092007; residual 0.025659 vs 0.025823.
- The stronger attribution check for this tiny patch is the five-product **T0 match at `-j 1`**, not a claim that the entire earlier patch stack is bitwise identical to upstream.

All per-product values, RSS and image statistics are retained in `science-summary.json`.

## Confirmed block-read failure boundary

An isolated real casacore in-memory fixture has two `CORRECTED_DATA` rows: row 0 defined, row 1 undefined. A normal read of selected row 0 returns twelve values. `ColumnBlock::Load(column, 0, 1)` throws because it also visits row 1. The production callers batch physical rows that can include excluded rows, so this must be addressed before claiming selection equivalence.

Evidence: `columnblock-selection-repro.log` and its source in the audit output directory. This is a **cache-boundary reproduction plus caller trace**, not yet a full `ContiguousMSReader`/`DirectMSRowProvider` selection integration test. The new homogeneous-block tests do not cover away this gap.
